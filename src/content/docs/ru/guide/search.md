Все поля поиска в интерфейсах L2NX работают по одним правилам: окно поиска вики и её списки, списки и выпадающие
списки админки. Страница продукта перечисляет, что он ищет у каждого вида записей; эта страница описывает, как
читается запрос и в каком порядке идут результаты.

## Основное

- Регистр не важен, `ё` и `е` — одна буква, лишние пробелы не учитываются.
- Если у записи есть названия на нескольких языках, ищутся все сразу: русское, английское или украинское название
  находит одну и ту же запись на любом языке интерфейса.
- Каждое слово запроса может быть началом слова: `сам дл` находит «Длинный меч самурая».
- Если вы сами отсортировали список по колонке, этот порядок важнее порядка по релевантности, описанного ниже.

## Длина запроса

| Запрос              | Работает с |
| ------------------- | ---------- |
| Текст: начало слов  | 2 символов |
| Число (id)          | 1 цифры    |
| Подстрока, опечатки | 3 символов |

Запрос из 2 символов находит записи, где с него начинается какое-то слово; с 3 символов текст совпадает и с
опечатками, а внутри слов — когда в нём есть слово из 3 символов (`ab cd` по-прежнему ищет только начала слов). Более короткий текстовый запрос отклоняется с подсказкой, что он слишком короткий; одна цифра
принимается, но что-то находит только там, где записи ищутся по id; в остальных местах (и для `#57`) результат пуст. Минимум считается для всего запроса, а не для каждого слова: в
`меч с` однобуквенное `с` всё равно работает как начало слова.

## Синтаксис

| Что вводите       | Что это значит                                                                     |
| ----------------- | ---------------------------------------------------------------------------------- |
| `слово1 слово2`   | должны совпасть все слова, в любом порядке                                         |
| `"точная фраза"`  | слова должны стоять рядом, как написано                                            |
| `-слово`          | исключаются записи, где этот текст есть где угодно, даже внутри слова              |
| `-"фраза"`        | исключаются записи с этой фразой                                                   |
| `57`              | запись с id 57 **и** записи, где какое-то слово начинается с «57»                  |
| `#57`             | только запись с id 57                                                              |
| длинный id (UUID) | для записей с UUID-идентификатором: эта запись и совпадения в тексте, как с числом |
| всё остальное     | ищется буквально                                                                   |

Примеры:

- `волк кираса` находит «Кираса Синего Волка»: порядок слов не важен.
- `"синего волка"` находит только названия, где «синего волка» стоит рядом.
- `меч -двуручный` находит мечи, кроме двуручных; исключённый текст ищется и внутри слов, поэтому `-руч` тоже убирает
  «Двуручный меч». `-` внутри слова (`анти-маг`) — обычный символ; отдельно стоящий `-` (или одни дефисы)
  игнорируется.
- `57` сначала находит запись с id 57, затем записи, где какое-то слово начинается с «57». Число длиннее, например
  `570`, находит и названия, где оно стоит внутри слова. Если цифр в названиях много, а нужен только id, вводите `#57`.
- Спецсимволы ищутся так, как набраны: `50%` находит названия с «50%», `(меч)` — «(меч)» вместе со скобками.
  Незакрытая кавычка, `%`, `_`, `*`, скобки и `OR` — обычные символы. Такой текст ищется внутри названий, поэтому
  ему нужно 3 символа: `+50` работает, `+5` сам по себе может ничего не найти.

Запрос из одних исключений (`-меч`) ничего не ищет и отклоняется, как слишком короткий.

## Опечатки

С 3 символов поиск прощает небольшие опечатки: `алимпиада` находит «Олимпиада». Совпадение с опечаткой всегда ниже
точного написания, поэтому чем больше букв введено верно, тем точнее результаты.

## Неверная раскладка

Запрос, набранный не в той раскладке, всё равно находит запись: `vtx` (клавиши «меч» в английской раскладке) находит
«Меч», а `ыцщкв` (клавиши «sword» в русской раскладке) находит «Sword». Распознаются пары русская ↔ английская и
украинская ↔ английская, если весь запрос набран в одной раскладке. Такие совпадения идут ниже всех прямых.

## Порядок результатов

Результаты идут от самого сильного совпадения к самому слабому:

1. Совпал id.
2. Название равно запросу.
3. Название начинается с запроса.
4. Каждое слово запроса — начало какого-то слова в тексте (слово со спецсимволами должно встретиться как набрано).
5. Текст содержит каждое слово запроса.
6. Текст совпал с опечаткой.
7. Запрос совпал в другой раскладке.

Среди записей с одинаково сильным совпадением:

- если продукт ищет по нескольким полям, выше совпадение в главном (например, в заголовке);
- выше популярные записи, если продукт считает популярность; как — написано на странице продукта;
- выше более короткое название: «Меч» выше «Меча самурая»;
- в остальном порядок идёт по id, чтобы страницы не перемешивались.

Популярная запись никогда не обгоняет более сильное совпадение: точное название остаётся выше подстроки на самой
посещаемой странице.

## Чего поиск не делает

- Нет `OR`, скобок и масок (`*`, `%`): они ищутся как обычные символы.
- Нет поиска по полю (`name:меч`): какие поля искать, решает продукт.
- Нет синонимов и словоформ: вводите начало слова (`олимп` находит «Олимпиада» и «Олимпиады»).
