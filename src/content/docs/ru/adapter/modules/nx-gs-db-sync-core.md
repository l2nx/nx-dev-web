Читает игровую базу и держит сущности, которые описывает хост (персонажи, кланы, предметы и другие), в синхроне с
платформой. Каждый цикл сравнивает контрольные суммы строк с предыдущим циклом и публикует только добавленные,
изменённые и удалённые строки.

## Координаты

```text
app.l2nx:nx-gs-db-sync-core
```

Java 8. Тег релиза `db-sync/vX.Y.Z`. Версии — на
[Maven Central](https://central.sonatype.com/artifact/app.l2nx/nx-gs-db-sync-core).

## Когда нужен хосту

Когда платформа должна видеть сохранённое игровое состояние сервера. Положите модуль в runtime classpath — core
найдёт его сам.

## Что предоставляет хост

- Один `JdbcConnectionSource` поверх пула сервера. Модуль только читает: каждое взятое соединение он переводит в
  read-only, поэтому для его части достаточно `SELECT` на игровые таблицы.
- Один `DbSchemaProvider`, который описывает, из каких таблиц и колонок состоит каждая сущность. Схема отличается
  между ядрами и сборками, поэтому она живёт в хосте.

Модуль держит кэш снапшотов на диске, поэтому строки, удалённые, пока сервер был выключен, приходят после
перезапуска. Каждому серверу нужна своя директория кэша, см. `l2nx.cdc-engine.persist.dir`.
