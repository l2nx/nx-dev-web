Этот глоссарий фиксирует термины объектной модели Lineage 2, игрового движка и клиентского протокола. Он нужен, чтобы
карта фич, документация движка и код этого репозитория использовали одно имя для одной вещи, хотя публичные семейства
сборок (Mobius, линия L2J, aCis, L2Emu и другие) называют одно и то же по-разному. Термин здесь — это концепт модели или
движка, а не фича.

## Виды сущностей

Каждый термин несёт одну отметку. Четыре вида называют сущности; пятая отметка — для того, что сущностью не является.

| Вид                         | Критерий                                                                                                                                   | Имя                                                       | Примеры                                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **template** / **instance** | Объект мира со своим object id, причём одно определение создаёт сразу несколько объектов                                                   | `<x>-template` для определения, `<x>` для каждого объекта | `item-template` / `item`, `npc-template` / `npc`, `reflection-template` / `reflection`, `vehicle-template` / `vehicle` |
| **unique entity**           | Собственная идентичность и одна запись на сущность: объект мира со своей записью данных либо группа, которую игра ведёт с живым состоянием | `<x>` без суффикса                                        | `door`, `castle`, `clan`, `party`, `siege`, `zone`, `olympiad-match`                                                   |
| **owned state**             | Не объект мира; принадлежит владельцу (персонаж, аккаунт, клан) и имеет своё состояние: уровень, таймер, срок действия                     | `<owner>-<x>` или существительное состояния               | `character-skill`, `premium`, `inventory`, `abnormal`                                                                  |
| **reference data**          | Данные, которые ищутся по id и никогда не инстанцируются                                                                                   | `<x>` без суффикса                                        | `skill`, `class`, `recipe`, `cubic`, `premium-plan`                                                                    |
| **concept**                 | Не сущность: процесс, механика, правило или понятие протокола                                                                              | `<x>` без суффикса                                        | `aggro`, `pathfinding`, `packet`, `bypass`, `event`                                                                    |

## Процедура именования

Отвечайте на вопросы по порядку; первое «да» определяет вид и имя.

1. _Существует ли вещь в мире как объект со своей runtime-идентичностью (object id), и может ли одно определение данных
   породить несколько таких объектов одновременно?_ Тогда определение — это `<x>-template`, а каждый объект —
   instance `<x>`. Монстры, петы, саммоны и стражи — всё это instance `npc`; травы, заряды (shots) и квестовые предметы —
   всё это instance `item`.
2. _Это игровая сущность со своей идентичностью, где одна запись — это одна сущность: объект мира, описанный собственной
   записью данных, либо группа, которую игра создаёт и ведёт с живым состоянием (она владеет вещами, а не принадлежит
   кому-то)?_ Тогда это **unique entity** с именем без суффикса; её данные и её живое состояние принадлежат одной сущности.
3. _Это не объект мира, а нечто, что держит владелец и что имеет своё состояние — уровень, таймер, срок действия?_ Тогда
   удерживаемая вещь — это **owned state**, с именем `<owner>-<x>` или простым существительным состояния, а её
   определение — reference data `<x>` (`character-skill` держит `skill` с уровнем и откатом).
4. _Иначе_ это **reference data** с именем без суффикса.

**Тест на concept.** У сущности есть идентичность и запись, поэтому на неё можно указать: «этот X» (этот клан, эта
дверь, этот матч); у concept нет ни того, ни другого (нет «этого aggro» или «этого pathfinding»). Процедура к concept не
применяется. Абстрактные уровни иерархии объектов, охватывающие несколько видов (`world-object`, `creature`,
`playable`), — тоже concept. Процедура именует сущности игрового домена; runtime-структуры движка (партиции, passes,
потоки, таймеры) — тоже concept.

## Соглашения

- **Канон.** Каноническим термином служит имя, которое уже используют серверы L2NX, если оно есть; иначе словарь Mobius
  High Five; иначе игровой термин, если он яснее. Канон пишется в kebab-case (`item-template`); идентификаторы
  семейства, клиента или пакета приводятся дословно.
- **Варианты продажи, расписания и списки** называются тем, чем они являются, и никогда не `-template`: `premium-plan`
  (вариант подписки: срок, бонусы, цена), `item-mall-product` (товар магазина), `item-auction-schedule` (запись
  расписания), `multisell-list` (таблица обмена).
- **Имена сборок канон не определяют.** Семейства называют `*Template` многих держателей reference data
  (`CubicTemplate`, `TransformTemplate`, `PremiumTemplate`); такие имена фиксируются только в колонке семейств.
- **Никаких key-value-мешков.** Key-value-хранилища семейств (Mobius `PlayerVariables`, `AccountVariables`,
  `GlobalVariables`) каноном не являются: каждое значение становится типизированным состоянием своего владельца (поле
  `character`, `game-account` или owned state уровня сервера). Их имена остаются только в колонке семейств.
- **Инстанс-зона.** Инстанс-зона — это `reflection`. Слово _instance_ означает только «объект, созданный из template» и
  никогда не используется для зоны.
- **Семейства.** «Mobius» — L2J Mobius (линии Interlude, High Five и Essence; High Five — линия, рефакторимая в этом
  репозитории). «Линия L2J» объединяет имена классов с префиксом L2, общие для L2J Server, L2jEternityWorld (`l2e`),
  L2jFrozen и L2Emu. aCis, Sunrise, L2JPremium, L2_Advanced, lunaris и другие публичные семейства названы там, где
  отличаются. Прочерк означает, что у семейства нет такого термина или он неизвестен.

## Как пользоваться глоссарием

- **Один канон для игрового сервера и платформы.** Код, данные, API и документация этого репозитория и сервисов
  платформы L2NX используют канонические термины этого файла; этот файл — источник истины.
- **Сначала найдите, потом называйте.** Перед тем как назвать сущность, таблицу, колонку, класс, DTO, REST-ресурс,
  событие или ключ конфига, несущие концепт Lineage 2, найдите термин здесь; если его нет, примените процедуру
  именования.
- **Новые термины добавляются в том же изменении**, которое их вводит, с видом и определением в одну строку.
- **Новых расхождений нет.** Неканоническое имя в существующем коде остаётся, пока этот код не тронут; изменение,
  владеющее контрактом, переименовывает его в сторону канона. Новое неканоническое имя не вводится никогда.

| Колонка                   | Значение                                |
| ------------------------- | --------------------------------------- |
| Термин                    | Канонический термин с отметкой вида     |
| Определение               | Одно предложение                        |
