Integration API — HTTP API, которое ваш сайт, панель или бот вызывает со своего сервера. Каждый запрос выполняется от
имени вашего тенанта — проекта на платформе L2NX — с его [API key](/ru/api/authentication/).

## Что доступно

| Сервис          | Что можно делать                                                                               | Scope                          | Справочник                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------------------------------- |
| Игровые серверы | Получать список игровых серверов вашего тенанта: `id` для `serverId`, `slug` для `Server-Slug` | `tenants.game-servers:read`    | [страница](/ru/api/tenants/) · [OpenAPI JSON](/ru/api/tenants/openapi.json)         |
| l2nx.top        | Читать ленту голосов, искать голоса по `ref`                                                   | `top.votes:read`               | [страница](/ru/api/top/) · [OpenAPI JSON](/ru/api/top/openapi.json)                 |
| Game data       | Читать шаблоны предметов ваших игровых серверов                                                | `gamedata.item-templates:read` | [страница](/ru/api/gamedata/) · [OpenAPI JSON](/ru/api/gamedata/openapi.json)       |
| Промокоды       | Активировать промокоды для игроков, например из личного кабинета                               | `gameservers.promo:redeem`     | [страница](/ru/api/gameservers/) · [OpenAPI JSON](/ru/api/gameservers/openapi.json) |

Справочные страницы каждого сервиса генерируются из его описания OpenAPI и перечислены в разделе **Integration API** в
боковом меню. Они обновляются автоматически с каждым релизом сервиса. Документ OpenAPI 3.1 каждого сервиса можно скачать
в JSON — из таблицы выше или со страницы справочника, например чтобы сгенерировать клиент.

## Хосты и пути

Каждый сервис отдаёт API под своим префиксом:

```text
https://{host}/{service}/v{N}/integration/...
```

| Сервис      | Хост                            | Пример                                                                  |
| ----------- | ------------------------------- | ----------------------------------------------------------------------- |
| l2nx.top    | `https://api.l2nx.top`          | `https://api.l2nx.top/top/v1/integration/votes`                         |
| API тенанта | `https://{tenant}.api.l2nx.app` | `https://myproject.api.l2nx.app/gamedata/v1/integration/item-templates` |

На хосте тенанта `{tenant}` — slug вашего тенанта. Тенант определяется по API key: ключ работает только на хосте своего
тенанта, ключ другого тенанта получает `403 API_KEY_TENANT_MISMATCH`.

## Заголовки

| Заголовок       | Когда                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------- |
| `Authorization` | Всегда: ваш [API-ключ](/ru/api/authentication/).                                                   |
| `Server-Slug`   | Операции одного игрового сервера: slug сервера, как в его URL (например, `main`). Нужен game data. |
| `Client-Ip`     | Вызовы вашего сервера по действию игрока (активация промокода из личного кабинета): IP игрока.     |

Тенант слать не нужно: он определяется хостом и API-ключом. Справочная страница каждой операции перечисляет заголовки,
которые она читает; операция одного игрового сервера без `Server-Slug` отвечает `400 SERVER_SLUG_REQUIRED`, а на сервер,
которого нет у вашего тенанта, — `404 SERVER_NOT_FOUND`. `Client-Ip` учитывается только с адресов вашего сервера,
зарегистрированных в платформе; с любого другого адреса платформа берёт адрес соединения. Чтобы их зарегистрировать,
напишите в [поддержку](/ru/support/).

## Версии

Мажорная версия — часть пути (`/v1/`). Внутри версии изменения обратно совместимы: новые эндпоинты, новые необязательные
параметры, новые поля в ответах. Незнакомые поля ответа игнорируйте. Ломающее изменение выходит под новой версией пути.

## Запросы и ответы

- JSON в обе стороны, UTF-8, `Content-Type: application/json` у запросов с телом.
- Время — ISO 8601 в UTC (`2026-10-12T09:33:20Z`), id — UUID.
- Поле без значения — `null`, никогда не пустая строка.

## Пагинация

Списки разбиваются на страницы одним из двух способов; в справке указано, каким пользуется эндпоинт.

- **Ленты с курсором**: `after` (id последнего полученного элемента) и `limit`. Пустая страница — конец ленты;
  продолжайте позже с того же курсора. Пример: лента голосов l2nx.top, `limit` от 1 до 500, по умолчанию 100.
- **Страницы**: `page` (с 0) и `size`. Пример: шаблоны предметов game data, `size` до 50. Больший `size` молча
  уменьшается до максимума, поэтому опирайтесь на метаданные страницы в ответе, а не на запрошенный размер.

## Ошибки

Ошибки следуют [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) и возвращаются как `application/problem+json`:

```json title="403 Forbidden"
{
  "type": "about:blank",
  "title": "Forbidden",
  "status": 403,
  "detail": "API key lacks a required scope",
  "code": "INSUFFICIENT_SCOPE",
  "traceId": "4f1c2a9b0d3e4f5a6b7c8d9e0f1a2b3c"
}
```

| Поле      | Смысл                                                                                                                  |
| --------- | ---------------------------------------------------------------------------------------------------------------------- |
| `status`  | HTTP-статус, совпадает со статусом ответа.                                                                             |
| `detail`  | Пояснение для человека. Не разбирайте его: текст может меняться.                                                       |
| `code`    | Машиночитаемая причина в `UPPER_SNAKE_CASE`, например `VALIDATION_FAILED`. Ветвитесь по нему. Есть не у каждой ошибки. |
| `traceId` | Id запроса. Укажите его, когда пишете в [поддержку](/ru/support/).                                                     |

Частые статусы:

| Статус | Когда                                                                                                        |
| ------ | ------------------------------------------------------------------------------------------------------------ |
| `400`  | Неверные параметры или тело.                                                                                 |
| `401`  | API key нет или он невалиден. См. [Аутентификация](/ru/api/authentication/#ошибки).                          |
| `403`  | Ключ известен, но не допущен: отозван, просрочен, нет scope, другой тенант, тенант приостановлен или закрыт. |
| `404`  | Ресурса нет или он не принадлежит вашему тенанту.                                                            |
| `429`  | Превышен rate limit, см. ниже.                                                                               |
| `5xx`  | Сбой на стороне сервера. Повторите с нарастающей задержкой.                                                  |

## Rate limits

Запросы ограничиваются по API key и по scope. Если в справке эндпоинта не сказано иное, ключ может отправить до 30
запросов подряд, запас восстанавливается со скоростью 60 запросов в минуту.

При превышении API отвечает `429` с кодом `RATE_LIMITED` и заголовком `Retry-After` — числом секунд до следующего
запроса. Подождите не меньше; не повторяйте запрос в плотном цикле.

```http title="429 Too Many Requests"
HTTP/1.1 429 Too Many Requests
Retry-After: 2
Content-Type: application/problem+json

{"type":"about:blank","title":"Too Many Requests","status":429,"detail":"Too many requests","code":"RATE_LIMITED","traceId":"4f1c2a9b0d3e4f5a6b7c8d9e0f1a2b3c"}
```

Нужен лимит выше для обоснованного сценария? Напишите в [поддержку](/ru/support/).
